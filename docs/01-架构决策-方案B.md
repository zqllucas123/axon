## 2. 为什么不用 codex（决策依据）

codex 是 Apache-2.0，**法律上可自由使用**，所以不是许可问题。真正的理由只有两条：

| 理由 | 说明 |
|---|---|
| **模型接入是硬伤** | `WireApi` 枚举只有 `Responses` 一个变体，且手写 Deserialize 把 `"chat"` 变成显式报错（`codex-rs/model-provider-info/src/lib.rs:60-67,78-88`）；连本地 Ollama / LM Studio 都被强制走 Responses（`:516,520`）。接 Claude/国内模型必须自建适配层 |
| **Rust×TS 跨语言成本** | 144 万行 Rust + 无语言级运行时；从 TS 集成必须自建进程边界协议。pi 是 TS，`Agent` 实例直接 in-process 编排（对比 kalo 为 Tauri 付出的 19 个 Rust 模块重写代价，见 02 §2.5） |

> ⚠️ 曾被写进 01 的论据「`multi_agent_v2` 还在 feature flag 后、随时可改可撤」是**错的**，已删除：
> 实测 `multi_agent_v2` 是 `Stage::Stable`（`features/src/lib.rs:1118-1123`），且 v1 `Collab` 已
> `default_enabled: true`，7 个 handler + 4 套集成测试，成熟度不是问题（02 §1.5）。
> 用错误论据做对的决策，会在下次评审时被质疑；放弃 codex 的正当理由只有上表两条。

**但 codex 的设计仍是重要参考**——Apache-2.0 允许读图纸。其 `AgentPath` 树形寻址、
`fork_turns`、`agent_roles` 权限模型都是本问题域已验证的设计，见 §5、§6。

## 3. 为什么不用 Rust 重写内核

曾考虑「抄 pi 分层 + Rust 实现」（方案 A）。实测数据否决了它：

```
packages/ai   23,555 行 TS / 177 文件
              44 个 provider
              31 个 API 方言实现
              12 个国内模型 provider：deepseek / kimi-coding / qwen(×3) /
                                      moonshot(国内外) / minimax(国内外) / ant-ling
```

- provider 层是**唯一买不到也抄不动的资产**：不是技术难度问题，是要持续跟 40+ 家厂商 API 变更的**永久人力负担**
- Rust 的收益对 Axon 不成立：codex 用 Rust 主因是沙箱强度与单文件分发；Axon 跑在自己机器上，沙箱需求远低于面向公众的 CLI
- 「Rust 才能单文件分发」不成立：pi 用 Bun 可编译单文件二进制
- 多 Agent 编排是应用层逻辑，与语言无关；用 Rust 只会让**需要反复迭代**的编排设计更慢
- 两人团队，全栈一门语言的杠杆 > Rust 的性能优势

## 4. 地基验证（已实测通过，依赖面结论按 02 §1.1/§1.4 修正）

方案 B 成立的前提是 pi 的包能独立依赖，已逐条验证：

| 验证项 | 结果 | 证据 |
|---|---|---|
| `pi-ai` 独立性 | ⚠️ 可独立依赖，但闭包 ~150 包 | 硬依赖四套 SDK：`@aws-sdk/client-bedrock-runtime`、`@anthropic-ai/sdk`、`@google/genai`、`openai`，另有 `@earendil-works/chord`→`esbuild` 原生二进制。**无 peerDependencies**，provider 靠动态 import 懒加载（`pi-ai/dist/api/lazy.js:46-49`）——打包风险见 §8 风险 B（01 原写「仅依赖 pi-telemetry」是错的） |
| `pi-agent-core` 独立性 | ✅ 仅依赖 pi-ai + telemetry + diff/ignore/typebox/yaml | `packages/agent/package.json` |
| **ESM-only**（新增项） | ⚠️ 两包的 `exports` 只有 `import` 条件，无 `require` | 两包 `package.json:exports`。desktop 主进程/preload 因此必须输出 ESM（`.mjs`），且 bundler 必须 external，否则动态 import 被静态提升（02 §4 风险 B） |
| 许可证 | ✅ 全部 MIT | `LICENSE:1`，各包 `license` 字段 |
| 导出面 | ✅ `exports` 分路径导出，可按需引入 provider/api | `packages/ai/package.json:13-40` |
| 多实例可行 | ✅ `Agent` 为独立类，自持 transcript | `agent.ts:173,216` |

**结论：不必重写 L0/L1，直接依赖即可。** 但依赖面比初评厚得多，且上游 minor 迁移频繁（02 §1.4：近 5 个 minor 中 4 个有 Breaking），所以依赖必须被收进**适配器边界**（§5 关键一节）并锁 0.85.1。

## 5. 分层架构

```
┌──────────────────────────────────────────────────────┐
│  L3  Axon 前端（Electron + TS）                        │
│      Agent 树可视化 / 角色编辑器 / 分身创建 UI         │
│      渲染进程 = 无状态薄壳；内核在主进程 in-process    │
└───────────────────┬──────────────────────────────────┘
                    │ IPC（主进程直调 AxonHost，不经 RPC）
┌───────────────────▼──────────────────────────────────┐
│  L2  Axon 编排层  ★ 自建，这是 Axon 的核心资产 ★       │
│      AgentRegistry / ContextForker / RoleLoader       │
│      MessageBus / Orchestrator / TreePersistence      │
├──────────────────────────────────────────────────────┤
│  适配器边界（AxonEngine / provider.ts）★ risk A 保险丝  │
│  只经此层 import pi，Agent 类型不泄漏到编排层          │
└───────────────────┬──────────────────────────────────┘
                    │ 依赖（不改源码，用官方钩子注入）
┌───────────────────▼──────────────────────────────────┐
│  L1  @earendil-works/pi-agent-core                   │
│      Agent 类：prompt/continue/steer/abort/subscribe  │
├──────────────────────────────────────────────────────┤
│  L0  @earendil-works/pi-ai                           │
│      44 provider / 31 API 方言 / 国内模型全覆盖        │
└──────────────────────────────────────────────────────┘
```

### 前端形态为什么是 Electron（01 §7 待定项 1 的结论）

- **pi 的 RPC 协议是单会话的**：`coding-agent/src/modes/rpc/rpc-mode.ts:58-62` 直接绑定单例 session，协议里不存在 session/agent 标识。多子 Agent 协作在 RPC 层无路可走，**必须 in-process**（02 §2.1）
- Tauri + in-process TS 内核是矛盾体：kalo 为此重写了 19 个 Rust 模块才把已有 Node 能力搬过去（02 §2.5）
- Electron 主进程直接持有 TS 内核，zero 跨语言成本

### ★ 适配器边界：为什么 + 怎么收

pi 上游正在把内核从 `Agent` 迁向 `AgentHarness` + lane-based Session（02 §4 风险 A：`agent-harness.ts` 约 510 行，22 处 `HarnessNotImplemented`）。若 `Agent` 类型四散到编排层，上游迁移 = Axon 全面返工。

因此 L2 只面对两个自产类型（`packages/kernel/src/engine.ts` / `provider.ts`）：

- `AxonEngine`（5 个方法：`prompt`/`waitForIdle`/`abort`/`subscribe`/`messages`）——编排层永远 import 不到 pi 的 `Agent`
- `ModelSource`（`createRegistry`/`streamFnOf`/`createFauxSource`）——pi-ai 与 pi-agent-core 是**两个独立发版的包**，各自封装

`scripts/check-bun-only.mjs` 第 6 项检查把这条规则变成 CI 约束：`packages/`、`apps/`、`examples/` 里 import `pi-*` 的文件白名单只有 `engine.ts`、`engine.contract.test.ts`、`provider.ts`。

### 关键：L2 如何接入 L1 而不改 pi 源码

**⭐ 主干机制是 `AgentTool.execute()` 的 async 语义**（`agent-loop.ts:679` `await prepared.tool.execute(...)`；02 §1.3 修正了 01 初稿）：

> pi 的 agent loop 会 await 每个工具的执行。一个"spawn 子 Agent"工具只要让 execute()
> 返回的 Promise 在子 Agent 跑完时才 resolve，**父 Agent 就自然挂起**——挂起-等待
> 不需要改 pi 源码，不需要钩子。这是 6.5 Orchestrator 的根基。

七个 `AgentOptions` 钩子（`agent.ts:98-123`）是**修边**，不是主干：

| 钩子 | Axon 用途 |
|---|---|
| `beforeToolCall` | 工具权限校验（角色白名单 × 审批档） |
| `afterToolCall` | 子 Agent 结果回灌父上下文 |
| `shouldStopAfterTurn` | 编排层决定是否继续 |
| `prepareNextTurnWithContext` | 注入 Agent 间消息 |
| `transformContext` | 实现分身的上下文裁剪 |
| `initialState` | 注入角色化 systemPrompt / model / tools |
| `streamFn` | **必填**——缺省时把 transcript 交给模型的那一步会直接炸 |

`subscribe()` 订阅 10 种 `AgentEvent`（`types.ts:428-443`），编排层据此驱动状态机与 UI。

## 6. L2 要建的六个组件

按依赖顺序，也是开发顺序：

### 6.1 AgentRegistry ✅ 已实现（`packages/kernel/src/registry.ts`）
Agent 实例的生命周期与寻址。借鉴 codex 的 `AgentPath` 树形寻址（`/root/task1/task_3`）。

职责：注册/注销、状态机（idle/running/waiting/done/failed/interrupted，显式 `TRANSITIONS` 白名单）、并发上限（拦 running 不拦 spawn）、用量沿父链汇总（根节点=全局总账）、级联删除（子先父后）。`DEFAULT_MAX_DEPTH = 2`（抄 TabTin）。

### 6.2 ContextForker ✅ 已实现（`packages/kernel/src/fork.ts`），默认值已反转
用户要的「纯净分身 vs 继承全部上下文」，在 pi 上就是切 `AgentContext.messages`：

```ts
// AgentContext = { systemPrompt, messages, tools }  (types.ts:412-419)
none     : messages = []                          // 纯净轻量分身 ★ 默认（见下）
lastRounds: messages = sliceRounds(parent, n)     // 折中档（codex fork_turns）
all      : messages = [...parent.messages]        // 继承全部（显式逃生门）
```

**默认值是 `none`，且是三个已上线产品独立收敛出来的结论，不是拍脑袋**（02 §3.1）：

- TabTin 最初默认 filtered 继承，后来改回 none 并留下复盘（`fork-query.ts:70-82`）：继承会把父原文「调 N 个 agent 做 X」灌进子上下文，弱模型被父原文带跑，thinking 里反复纠结「父原文 vs 自己的 directive」
- kalo 的 subagent 只传 prompt 文本，不复制父历史
- tutti 不设默认，强制每次显式三选一（none/recent/full）

结论：子 Agent 的输入应当是**结构化的 task 契约**（systemPrompt + 明确任务），而不是父会话原样。`all` 保留，降级为显式逃生门——内置角色里只有 Axon5 用它（其职责就是核对「实际做的 vs 当初说的」，没有上下文无从核对，见 `apps/desktop/src/main/roles.ts`）。

另需按 **round 边界**切，不能按消息条数切——否则会切出孤儿 toolResult（已有 37 个单测覆盖，含悬空 toolCall 修复）。

### 6.3 RoleLoader
Axon1~5 的声明式定义。角色 = 一个配置文件（抄 TabTin 的 `packages/agents/<name>/agent.json`），含 `instructions` / `tools 白名单` / `approval 档` / `forkMode 默认值`。

**能力 = 工具白名单 × 审批档，两个正交维度**（抄 TabTin 的 `AgentMode × ApprovalMode`，02 §3.3）：

- `tools` 白名单是**能力**限制（"测试 Agent 只读"）
- `ApprovalMode = always_ask | auto | full_access` 是**信任度**（"开发 Agent 改代码前问我"）
- 二者已在 `packages/protocol/src/agent.ts` 落地，内置角色的双正交取值见 `apps/desktop/src/main/roles.ts`（Axon3 全能力配最严审批，Axon5 只读配 auto）

**设计约束（抄 codex `role.rs:91-106`）：角色只能减能，不能越权。** 子角色工具集 = 父角色工具集 ∩ 自己白名单（AxonHost 已实现，`host.test.ts` 有"子不能越过父"用例）。

**当前状态**：角色定义已从纯 TS 常量升级为「TS 内置 + `~/.axon/roles/*.json` 用户文件」两级；用户可覆盖内置（overridesBuiltin 标记）；校验权威在 RoleLoader；UI 角色编辑器已上线（React）。schema 即 `RoleDefinition`，落盘带 `version: 1` 外箱。

### 6.4 MessageBus —— 收敛为「枚举化协作动作 + 落账」，不做自由消息总线
拆解自 tutti（02 §3.2）：

- 协作动作该**枚举化**（tutti 的 `consult|fork|delegate|handoff`，`biz/collabrun/model.go:17-27`）：每个动作有明确触发与落账，比"任意 Agent 随便发消息"可控得多
- 交接用 URI 引用 `mention://agent-session/<id>`，**不拷贝 transcript**（拷贝会膨胀子上下文，且失去单一真相源）
- **明确反对把 planning/review 做成特权模型角色**：那不是"协同"，是给编排层开天窗（信任落在机制上，不落在角色上）
- 审批穿透父级：子 Agent 的审批请求沿父链向上（TabTin `permissions/subagent-hitl.ts:9-17`）

### 6.5 Orchestrator
主干是 **`AgentTool.execute()` 的 async 语义**（§5 已述）：挂起-等待不需要改 pi 源码。

工具面抄 TabTin 五件套（02 §3.3，比 codex 六件套更贴合轮转语义）：`background` / `wait` / `check` / `message` / `interrupt`（`agent-spawn` 已由 agent 工具承担）。

### 6.6 TreePersistence
pi 的 session 是单线 JSONL，多 Agent 树需扩展。抄 kalo 的落盘布局（02 §2.4）：

```
~/.axon/agent/sessions/<编码cwd>/<parentSessionId>/subagent/<childId>/*.jsonl
```

关键在 `list_sessions()` 用**非递归扫描**——天然排除子 Agent 文件。树结构（父子关系）与单线 JSONL 文件解耦。

# Axon 架构决策：方案 B（TS 内核 + 自建编排层）

> 状态：**已定稿**
> 日期：2026-09-12
> 前置文档：`00-内核选型调研报告.md`

---

## 1. 决策结论

**Axon = 直接依赖 `pi-ai` + `pi-agent-core` 作为执行内核，自建多 Agent 编排层（L2），全栈 TypeScript。**

推翻了 00 号报告"codex 作内核"的结论。变更理由见 §2。

---

## 2. 为什么不用 codex（决策依据）

codex 是 Apache-2.0，**法律上可自由使用**，所以不是许可问题。真正的理由：

| 理由 | 说明 |
|---|---|
| **它是产品不是库** | roadmap 服务 OpenAI；`multi_agent_v2` 还在 feature flag 后，随时可改可撤 |
| **核心价值不该寄生** | 多 Agent 编排是 Axon 的立身之本，建在 codex 上则该能力是别人的，我们只能在 UI 上差异化 |
| **模型接入是硬伤** | `WireApi` 只剩 Responses，Chat Completions 已删除；接 Claude/国内模型必须自建适配层 |
| **上游跟踪成本** | 144 万行 Rust，fork 即养巨兽 |

**但 codex 的设计仍是重要参考**——Apache-2.0 允许读图纸。其 `multi_agent_v2` 是本问题域已验证的设计，见 §5。

## 3. 为什么不用 Rust 重写内核

曾考虑「抄 pi 分层 + Rust 实现」（方案 A）。实测数据否决了它：

```
packages/ai   23,555 行 TS / 177 文件
              44 个 provider
              31 个 API 方言实现
              12 个国内模型 provider：deepseek / kimi-coding / qwen(×3) /
                                      moonshot(国内外) / minimax(国内外) / ant-ling
```

- provider 层是**唯一买不到也抄不动的资产**：不是技术难度问题，是要持续跟 40+ 家厂商 API 变更的**永久人力负担**
- Rust 的收益对 Axon 不成立：codex 用 Rust 主因是沙箱强度与单文件分发；Axon 跑在自己机器上，沙箱需求远低于面向公众的 CLI
- 「Rust 才能单文件分发」不成立：pi 用 Bun 可编译单文件二进制
- 多 Agent 编排是应用层逻辑，与语言无关；用 Rust 只会让**需要反复迭代**的编排设计更慢
- 两人团队，全栈一门语言的杠杆 > Rust 的性能优势

## 4. 地基验证（已实测通过）

方案 B 成立的前提是 pi 的包能独立依赖，已逐条验证：

| 验证项 | 结果 | 证据 |
|---|---|---|
| `pi-ai` 独立性 | ✅ 仅依赖 `pi-telemetry` | `packages/ai/package.json:65` |
| `pi-agent-core` 独立性 | ✅ 仅依赖 pi-ai + telemetry + diff/ignore/typebox/yaml | `packages/agent/package.json` |
| 许可证 | ✅ 全部 MIT | `LICENSE:1`，各包 `license` 字段 |
| 导出面 | ✅ `exports` 分路径导出，可按需引入 provider/api | `packages/ai/package.json:13-40` |
| 多实例可行 | ✅ `Agent` 为独立类，自持 transcript | `agent.ts:173,216` |

**结论：不必重写 L0/L1，直接依赖即可。** 这比原计划的「抄设计重写」节省大量成本。

## 5. 分层架构

```
┌──────────────────────────────────────────────────────┐
│  L3  Axon 前端（Electron/Tauri + TS）                 │
│      Agent 树可视化 / 角色编辑器 / 分身创建 UI         │
└───────────────────┬──────────────────────────────────┘
                    │ 进程内直调 或 JSON-RPC（见 §7）
┌───────────────────▼──────────────────────────────────┐
│  L2  Axon 编排层  ★ 自建，这是 Axon 的核心资产 ★       │
│      AgentRegistry / ContextForker / RoleLoader       │
│      MessageBus / Orchestrator / TreePersistence      │
└───────────────────┬──────────────────────────────────┘
                    │ 依赖（不改源码，用官方钩子注入）
┌───────────────────▼──────────────────────────────────┐
│  L1  @earendil-works/pi-agent-core                   │
│      Agent 类：prompt/continue/steer/abort/subscribe  │
├──────────────────────────────────────────────────────┤
│  L0  @earendil-works/pi-ai                           │
│      44 provider / 31 API 方言 / 国内模型全覆盖        │
└──────────────────────────────────────────────────────┘
```

### 关键：L2 如何接入 L1 而不改 pi 源码

`AgentOptions`（`agent.ts:98-123`）已暴露全部所需钩子：

| 钩子 | Axon 用途 |
|---|---|
| `beforeToolCall` | 拦截 `spawn_agent` 等编排工具；工具权限校验 |
| `afterToolCall` | 子 Agent 结果回灌父上下文 |
| `shouldStopAfterTurn` | 编排层决定是否继续（等待子 Agent 时挂起） |
| `prepareNextTurnWithContext` | 注入 Agent 间消息 |
| `transformContext` | 实现分身的上下文裁剪 |
| `initialState` | 注入角色化 systemPrompt / model / tools |
| `streamFn` | 复用 pi-ai，或按角色换模型 |

`subscribe()` 订阅 10 种 `AgentEvent`（`types.ts:428-443`），编排层据此driving 状态机与 UI。

## 6. L2 要建的六个组件

按依赖顺序，也是开发顺序：

### 6.1 AgentRegistry
Agent 实例的生命周期与寻址。借鉴 codex 的 `AgentPath` 树形寻址（`/root/task1/task_3`）。

职责：注册/注销、状态机（idle/running/waiting/done/failed）、并发上限、父子关系。

### 6.2 ContextForker ★ 最直接的需求映射
用户要的「纯净分身 vs 继承全部上下文」，在 pi 上就是切 `AgentContext.messages`：

```ts
// AgentContext = { systemPrompt, messages, tools }  (types.ts:412-419)
none : messages = []                          // 纯净轻量分身
all  : messages = [...parent.messages]        // 继承内核全部上下文
lastN: messages = sliceTurns(parent, n)       // 折中档（codex 验证过最实用）
```

注意：需按 **turn 边界**切，不能按消息条数切——否则会切出孤儿 toolResult。

### 6.3 RoleLoader
Axon1~5 的声明式定义。借鉴 codex `agent_roles`：一个角色 = 一个配置文件，含 `systemPrompt` / `model` / `tools白名单` / `forkMode默认值`。

**设计约束（抄 codex `role.rs:91-106`）：角色只能减能，不能越权。** Axon5 可以禁 shell，但不能给自己开父级没有的权限。

### 6.4 MessageBus
Agent 间通信，「协同工作」的核心。借鉴 codex `InterAgentCommunication`。
消息类型至少：`NewTask`（触发对方 turn）、`Message`（仅入上下文不触发）。

### 6.5 Orchestrator
编排策略。工具族抄 codex 的六件套：
`spawn` / `send_message` / `wait` / `list_agents` / `interrupt` / `followup_task`

### 6.6 TreePersistence
pi 的 session 是单线 JSONL，多 Agent 树需扩展。可复用 pi 的 JSONL + fork/clone 思路。

## 8. 风险登记

| 风险 | 等级 | 应对 |
|---|---|---|
| pi 上游 API 变动（0.84.2，未到 1.0） | 中 | 锁版本；L2 对 L1 做薄封装隔离 |
| pi 官方拒绝 subagent/MCP，不会有上游支持 | 中 | 已知；L2 本就自建，不依赖上游 |
| 按消息切片导致孤儿 toolResult | 高 | ContextForker 必须按 turn 边界切 + 单测覆盖 |
| 多 Agent 并发下的 token 成本失控 | 中 | Registry 层设并发上限 + 预算熔断 |
| pi 崩溃恢复未实现（durable program counter 为零实现） | 低 | Axon 自建 TreePersistence 时一并解决 |

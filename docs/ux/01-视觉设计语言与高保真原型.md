## 0. 这份东西是什么 / 不是什么

**是**：把 `00-信息架构与屏幕清单.md` 的文本 IA 翻成可点、可截图、可评审的视觉稿，并给出一套可以直接落到 React 19 的设计令牌（CSS 变量）与组件骨架。

**不是**：
1. 不是实现代码。`mockups/assets/axon.css` 是**令牌与组件形状的说明书**，MU 落地时应转成 renderer 的样式层，而不是整份拷过去；
2. 不是协议承诺。原型里出现的任何数据，凡是当前协议拿不到的，都在界面上标了红色缺口标签（G1~G9），**看到红标就意味着 M4/M6 得先补协议**；
3. 不是交互规格。动效、键盘流、焦点管理留给 MU。

## 2. 设计语言：从 Codex 抄什么、不抄什么

参照对象是 Codex 桌面端（用户提供的截图）。**抄的是它的克制**，不是它的布局：

| 维度 | 取值 | 理由 |
|---|---|---|
| 表面 | 三层暖灰 `#f2f1ee` 侧栏 / `#fcfcfb` 画布 / `#ffffff` 卡片 | 暖灰比冷灰耐看；三层足够表达层级 |
| 分层 | **只用 1px 描边，全局零投影**（浮层也不例外） | 阴影在密集信息界面会显脏；Axon 的卡片密度比 Codex 更高。**浮层（`.menu`）靠「白底 `--bg-elev` + `--line-strong` 强描边」与暖灰侧栏拉开层次**，而不是破例加阴影 |
| 图标 | 24 视窗 / 1.6px 描边 / 圆头 / currentColor，尺寸只有 14·16·18·20 | 与 Codex 一致；禁止填充与双色图标 |
| 主按钮 | 近黑 `#2b2a27` + 圆形发送钮 | 全局唯一的高对比元素，天然成为视线终点 |
| 语义色 | 全部降饱和：运行 `#a8791a`、完成 `#4a7a52`、等待 `#6f6e84`、错误 `#b0473b` | 只用于 7px 圆点 / 22px 标签 / 5px 进度条，**永不铺大面积** |
| 字阶 | 会话 15px/1.75、界面 14px、元信息 11–13px、标题 17–22px | 会话正文放大一档，长文阅读优先 |
| 半径 | 标签 6 → 按钮 8 → 卡片 12 → 面板 16 → 气泡 20 | 半径梯度即层级梯度 |

**没抄的**：Codex 的右侧「环境信息」是项目级静态信息；Axon 右侧换成**会话检视栏**：顶部常驻「本会话成员」树，下方跟随选中成员的详情（角色/模型/ForkMode/工具数/在等谁/用量）+ 本会话账本，因为 Axon 的第一疑问永远是「这个任务里谁在干、这个分身能干什么、它在等谁」。

### 2.1 四条硬规矩（把 Codex 风格落到多分身场景的关键）

0. **左栏管「会话之间」，右栏管「会话之内」**（用户 2026-09-14 拍板，详见 02 §3.6）：分身树、成员信息、会话账本、会话用量都是**会话粒度状态**，一律渲染在右侧检视栏并随会话切换整体换掉；左侧边栏只有全局导航 + 会话列表（进行中 / 最近），**不渲染任何会话内部结构**。
1. **分身身份靠位置，不靠颜色**：成员树用缩进 + 引导竖线表达父子，不给每个分身分配主题色（3 个以上主题色就失效，且与语义色打架）。
2. **一屏一个焦点分身**：会话屏只渲染当前选中分身的流。跨分身信息一律走账本（S4）与收件箱（S5）——这是对现有混流 `EventLog` 的正式否定（00 §1：`[source]` 前缀打平不可扩展）。
3. **需要你决策的东西永远有 chip**：顶栏右侧常驻三枚 chip（预算 / 待批 / 账本），任何屏都能一眼看到并点进去。不做横贯全宽的 banner（banner 会在 warning 常驻时变成噪声）。
   **chip 随屏切作用域**（见 02 §3.4）：会话屏读本会话口径，全局屏读跨会话口径，两套数字永不混用。

## 3. 会话流只有六种元件

S2 是最难的一屏，也是最容易失控的一屏。原型把它约束成六种元件，**新增信息一律做成「卡片」，不许新开区块**：

| 元件 | 形态 | 对应事件/数据 |
|---|---|---|
| 用户气泡 | 右对齐、sunken 底、20px 圆角 | `agent.messages` 中的 user 消息 |
| 助手正文 | 无气泡、无头像，直接铺画布，靠留白分段 | `message.start/delta/end`（delta 为 **G2.2** 缺口） |
| 活动行 | 图标 + 一行灰字（「已读取文件」「本轮用时 55 秒」） | `agent.tool.start`、`agent.turn.end` |
| 折叠块 | 默认收起（thinking、长工具输出） | thinking 形状为 **G6.1** 缺口 |
| 卡片 | 头（图标+名+路径+状态标签）/ 身 / 脚（动作），四类共用骨架：工具、审批、协作、错误 | `tool.start/update/end`（**G2.3**）、`approval.request`（**G2.4**）、`ledger.recorded`（**G8.1**） |
| 输入区 | 底部常驻，16px 圆角、单描边、底排放「审批档」与「角色·模型」开关 | `agent.prompt` |

消息级成本（`1,842 in · 613 out · $0.031`）放在助手正文的动作行右侧——**这是 G6.2 缺口**，M6 真模型尖峰前拿不到可靠粒度，MU 落地时若仍缺就整行隐藏，不许拿 turn 级数据冒充。

## 4. 原型对协议缺口的可视化（评审时按这个清点）

原型不回避缺口，而是把它们画出来，便于 M4 评审逐条拍板：

| 屏 | 界面上标出的缺口 | 含义 |
|---|---|---|
| S1 | G4.2（当前任务文本）、G4.6（waitingOn / parked 位次） | 「它在干什么 / 在等谁」目前快照给不出，列表第二行就是空的 |
| S2 | G2.2 / G2.3 / G6.1 / G6.2 / G4.3 / G4.5 | 流式、工具分块、thinking、逐条成本、生效模型、生效工具集 |
| S2/S5 | G2.4 / G5.1 / G1.1 / G1.2 / G1.3 | 审批全链路：请求发射、请求体带父链、响应端、提问、重连补拉 |
| S4 | G7.1 / G7.2 / G8.1 / G8.2 / G4.1 / G5.2 | 账本查询、adoption 表态、落账推送、稳定 sessionId、usage 分片 |
| S6 | G7.3 / G9.1 / G9.2 | 档位可查询、`limitUsd` 语义错、frozen 无恢复通道 |
| S3 | G4.3、G10.2、G10.4 | 类型编辑器故意**不开放** model 字段（写了 host 也忽略，会误导）；团队这层协议整个不存在 |
| S0 | G10.1、G10.2 | 会话这个容器本身没有协议（只有 `agent.spawn`） |
| S2-solo | G10.5 | 单兵会话无法就地升级为团队会话并继承上下文 |
| S1/S2 | G10.3 | 快照上没有会话归属与 team 引用 |
| S8 | G11.1~G11.11 | 配置面缺口：无写入器、主题/语言/菜单栏项为纯新增、软线与 maxDepth 不可配等（完整条目见 03 §5） |

> 设计上的取舍：凡是「协议给不出但用户一定会问」的信息（在等谁、当前任务、生效模型），原型都保留了位置并标红。**M4 若决定不补，MU 必须把这些位置整块删掉，而不是填假数据。**

## 5. 与后续里程碑的接口

1. **M4（协作动作与落账）**：S4/S5 是 M4 协议面的直接消费者。评审时可把 `s4-ledger.html` 的「账目详情」表与 00 §6.1 的 `LedgerRecord` 形状并排看；`s5-inbox.html` 的穿透链即 `PendingRequest` 重定义（G5.1）的验收口径。
2. **M6（真模型尖峰）**：S2 的流式 / thinking / 工具卡 / 逐条成本四项形态需由真模型验证方言后才能定稿。原型给的是**上限形态**（全都画出来了），尖峰后按实际能拿到的数据做减法。
3. **MU（产品化 UI 实现）** → ✅ **MU-2 已落地（2026-09-16）**：S0/S1/S2/S2-solo/S3 五屏按本文件与原型逐值对齐实现，代码在 `apps/desktop/src/renderer/`，逐屏对照见 `docs/milestones/MU-2-renderer-core.md` §4.5/§十三。
   - 令牌直接搬 `assets/axon.css` §1（`:root`）→ 落成 **`apps/desktop/src/renderer/styles/tokens.css`**（四份 CSS 由构建期拼成一份）；
   - 组件按 §3 的六元件 + 列表/表格/面板落成 React 19 组件，**保持 L3 薄壳：组件只渲染 + 发意图**；
   - 侧栏会话列表与顶栏 chip 是仅有的两处「跨会话」渲染，右栏成员树是仅有的一处「跨分身」渲染，其余一律单焦点；
   - 右侧检视栏的三个视图（成员树 / 成员详情 / 会话账本）都按会话粒度重建；
   - 实现顺序按 02 §7：**S0 → S2-solo → S2 团队会话 → S1 → S3**；设置窗（S8）不在这条序上，它由 03 §6 单独定序。

## 6. 已知不足（下一版再补）

- 无空态 / 首次启动 / 无角色 / 无分身的形态；

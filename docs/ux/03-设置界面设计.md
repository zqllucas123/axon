## 0. 定位与边界

**是**：把今天散落在三个地方（`~/.axon/config.json` 文件、`AXON_*` 环境变量、主进程里的硬编码默认值）的可配置项，收拢成**一个界面上能看见、能改、能解释结果**的设置窗，并逐项标注它落到代码的哪一行。

**不是**：

1. 不改实现代码。本文与原型只交付设计；任何 `.ts` / `.tsx` 改动属于 MU 实现里程碑（AGENTS.md §4.4：UX 支线只写 `docs/ux/**`）。
2. **不发明配置项**。每一项要么已经有代码落点（配置文件字段 / `HostOptions` 字段 / 已有 IPC 命令），要么被显式标成「新增需求」并进 §5 的缺口清单。Axon 的纪律是「协议给不出就删掉界面元素，不填假数据」（01 §4），这里同理：**配置面给不出的项，要么标缺口、要么不放。**
3. 不做团队/角色的编辑界面。团队与 Agent 类型归 S3（`s3-teams.html`），设置窗只放一个跳转。**同一个东西不设两个编辑入口**。

## 1. 为什么设置是「独立窗口」，而不是左栏第 7 项

左栏的 6 项导航（S0 新建 / S1 会话 / S3 团队 / S5 收件箱 / S6 预算 / S7 恢复）**全部是会话主轴的屏**。设置放进去会同时破坏两件事：

| 麻烦 | 说明 |
|---|---|
| 职责轴不同 | 左栏管「**会话之间**」（01 §2.1 硬规矩 0）；设置是**应用级**，不属于任何会话。放进去后，「当前在设置里」时左栏该高亮那一行、右栏（会话检视栏）该显示谁，都答不上来 |
| 状态轴不同 | 顶栏三枚 chip（预算 / 待批 / 账本）**随屏切作用域**（01 §2.1 硬规矩 3）。设置窗里没有会话上下文，chip 只能显示跨会话口径 —— 一个不参与会话的窗口却挂着会话横幅，语义就是错的 |

所以：**独立窗口**，窗口自带一条 250px 子导航。代价是「回到应用」要一次点击，这个代价由左上角常驻的 `返回应用` 承担。

### 1.1 入口：左下角账号菜单（用户拍板 2026-09-15）

设置没有左栏导航位，入口是**侧栏底部的账号行**：头像 + 用户名整行可点 → 上弹菜单 → `设置…`。

| 菜单项 | 去向 | 代码现状 |
|---|---|---|
| `设置…`　⌘, | S8 设置窗（general pane） | 新增 |
| `打开配置目录`　`~/.axon` | 系统文件管理器 | `role.openDir`（`ipc.ts:90-102`）**已实现但只开 roles 子目录**，开 `~/.axon` 根目录需扩展 |
| `关于 Axon` | S8 设置窗 `#about` | 新增 |

两条实现约束：
1. **`⌘,` 与菜单项同一个行为**，且语义是「聚焦已开的设置窗，没开则新开一个」—— **不是导航**，不得把主窗内容替掉（原型是静态 html，只能用跳转模拟，实现时注意别照抄）。
2. **齿轮不得做成裸链接**。早先版本把 `side-foot` 的齿轮图标直接当链接，已推翻；账号菜单才是唯一鼠标入口。

> 实现前的真实状态：在这次补之前，**设置根本没有入口** —— `side-foot` 的齿轮是个没有 `href` 的装饰图标，全仓唯一能到 `s8-settings.html` 的路径是原型索引页 `index.html`。

### 1.2 什么不进设置（用户拍板 2026-09-15）

曾考虑把「预算与用量」「会话总览」整屏搬进设置，**结论是不搬**，三条理由：

| # | 理由 |
|---|---|
| 1 | **设置是独立窗**，而这两屏的每一行都是**跳板**（总览点进会话、预算页「按会话」点进 `s2-usage.html`）。从独立窗跳进主窗的某个会话 = 跨窗导航 |
| 2 | **频次与徒标**：收件箱的 `2`、总览的活跃会话数是催办信号，必须在主窗常驻可见；藏进低频配置容器等于没人看得见 |
| 3 | **「预算与用量」本就是两种东西混在一屏**：上限配置（全局软/硬线）**已经在设置里**（§3.3 预算组）；剩下的今日已用 / 谁进了 warning / 成本构成是**仪表盘**，不是设置 |

落到界面上：设置侧栏第二组标题从「配置」改为 **「在主窗里管」**，两项用 **↗ 外链图标**（而非与 pane 切换同形的 `chevR`），并配一句说明「这两项会回主窗打开」。目的是消除「以为内容在设置里、点了却被扔出去」的预期落差。

> 与 02 §3.6 同一逻辑：**每个表面只负责一个粒度**。左栏=会话之间，右栏=会话之内，设置窗=应用级配置。三层互不重叠。

### 2.3 一条硬规矩：**每行必须有「一句说明」**

Codex 的设置窗里，标题下都有一行灰字解释这个开关管什么。Axon 更需要它，原因是 Axon 的设置项**几乎全都能改变安全边界**（审批档、并发、预算、裁决权）。一句说明的最低要求：

1. **说清默认值**与被谁覆盖（例：默认审批档「角色自带 approval 时以角色为准，且只能更严」）；
2. **说清边界语义**（例：预算硬线「到线只挡新起点，在跑的不杀」）；
3. 实现细节不写进说明 —— 那是 `.ann` 标注（`⌘/` 切换）的活。

这与 01 §2 的「语义色只用于小面积」是同一种克制：**设置页的文字量必须靠层级控制，不靠加粗和颜色**。

**设计说明（三条）**：

1. **审批档那一行要写「只能更严」**。选型上有两种直觉（「全局默认 = 下限，角色可更松」vs「= 上限」），代码的答案是后者：角色只能减能不能越权（`fork.ts` 的 `intersectTools`，AGENTS.md §5 不变量）。界面上说反了会直接造成安全误解。
2. **「编排工具豁免」用标签而非开关**。它是架构不变量（决策 D5：豁免的理由是「否则一次 delegate 会同时弹两次确认」），做成开关等于把不变量交给用户配置 —— 而 01 §4 的纪律是「协议给不出的位置要么标红要么删掉」，这里是「给了会误导」。
3. **超时值有两种单位混在一页**：审批超时与空闲看门狗是「分钟」，`agent_wait` 默认是「秒」。原型里用单位标签（`5 分钟` / `600 秒（常量）`）明示，避免用户在两处输入同一个数字以为语义相同。

## 4. 交互规格

### 4.1 保存时机：**没有「保存」按钮**

改完即生效（写入 + 立即应用到下一次 spawn / prompt）。理由：Axon 的设置项没有「批量提交」的语义，逐项生效更容易解释「为什么这个改完立刻有用、那个要重启」。需要重启的项在说明里标注。**代价**：需要一个「脏值回滚」策略 —— 写入失败（磁盘只读、JSON 损坏）时行内报错并把控件回滚到真实值，而不是假装成功。

### 4.2 环境变量覆盖必须显示为**只读**（本节最重要的设计点）

优先级是环境变量 > 配置文件：`env.AXON_BASE_URL || p.baseUrl`、`env.AXON_API_KEY || p.apiKey`（`model-config.ts:79-80`），`AXON_MODEL`（`:95`），`AXON_PROVIDER=faux` 强制降级（`:74-81`），`AXON_CONFIG` / `AXON_ROLES_DIR` 决定路径（`:53`、`index.ts:58`）。

于是有一个**必然的界面要求**：当这些 env 存在时，对应控件必须**置灰 + 显示「已被环境变量 AXON_BASE_URL 覆盖」**。否则用户改了 Base URL、界面显示改成功了、实际请求还走旧地址 —— 这是最难排查的一类问题（配置生效性不可见）。

同理，`AXON_ROLES_DIR` 存在时「角色目录」显示的是该 env 的值。原型当前没有画这个态，属**待补**（§5 G11.14）。

### 4.3 降级必须与顶栏同源

faux 降级有四种原因（`model-config.ts:82,97` + 清单为空 + 指定模型不在清单内，`index.ts:88-115`），今天它们只体现在「顶栏 chip」上。设置页的「执行模型」行必须**读同一个 reason 字段**（不能各算一次），否则两处会不一致。这要求 `config.get` 的返回值里带解析结果（§6）。

### 4.4 校验

| 项 | 规则 |
|---|---|
| Base URL | 必须 `http(s)://`；末尾斜杠自动剥（`provider.ts:175`） |
| 预算 / 并发 / 深度 / 超时 | 非负整数；预算 `0` 的语义是「关闭熔断」，界面上要写成 `0 = 不限制` 而不是报错 |
| API Key | 只回显脱敏值（`maskKey`，`model-config.ts:113-115`）；**不在日志与事件里出现明文** |
| 模型 id | 非空、不重复；`defaultModel` 必须是清单里的 id（与 `model-config.ts:96` 同规则） |

### 4.5 危险操作

只有一处（重置所有设置）。危险区规则：**红描边整组 + 二次确认对话框 + 明确写出不动什么**（「只重置设置与 `config.json`，不动角色目录与团队」）。不做「输入 DISABLE 才允许」那类仪式 —— 这个操作可恢复（重新填一遍），过度仪式会让真的想重置的人多花一分钟。

### 4.6 空态

- 无角色目录 / 目录不存在：`在访达中打开` 按钮照常可用（`role.openDir` 幂等），不做空态引导。
- 模型清单为空：**这是 faux 降级的四种原因之一**，所以「执行模型」行显红标签 + 「添加模型」为主按钮；不做独立空屏。

## 6. 协议需求（最小集）

设置界面**不引入任何编排逻辑**（AGENTS.md §5：编排决策零残留），它只需要两条新命令：

```ts
/** 读配置 + 读解析结果（faux 原因、env 覆盖清单），供设置页渲染三态。 */
'config.get': {
  payload: Record<string, never>;
  result: {
    config: AxonConfig;          // 文件里的原文（apiKey 已 maskKey）
    envOverrides: string[];      // 生效的 AXON_* 变量名，供界面置灰
    resolution: { kind: 'faux' | 'openai'; reason?: string };  // 与顶栏同源（§4.3）
  };
};

/** 局部更新。只允许白名单路径，未知路径报错而不是静默丢弃。 */
'config.patch': {
  payload: { patch: Record<string, unknown> };   // 建议 JSON Merge Patch 子集
  result: { accepted: boolean; errors: RoleIssue[]; config: AxonConfig };
};
```

**为什么不是「每个设置一条命令」**：设置项约 20 个，逐项一条命令会造出 20 条几乎同形的 IPC（且每加一个配置项就要动协议）。`config.patch` + **服务端白名单**（主进程只接受已知路径）既省协议，又不放弃校验 —— 校验和边界永远在主进程，符合分层纪律。

**为什么返回值带 `envOverrides` 与 `resolution`**：这两个都是「主进程才知道的真相」（env 优先级 `model-config.ts:79-80`、faux 判定 `index.ts:88-115`）。让渲染层自己算，等于把同一份逻辑写两遍，且必然出现两处不一致（§4.2 / §4.3）。

**另需（可复用现有命令，不新增）**：`role.openDir`（已实现，`index.ts:264`）、`ledger.getAdoptionPolicy` / `ledger.setAdoptionPolicy`（已实现，`host.ts:971`）、`budget.get`（已实现，`host.ts:975`）。

**MU-1 实测形态（2026-09-15 交付，与上面的设想三处不同）**：

1. `config.get` 返回 `ConfigSnapshot { config; envOverrides; paths; resolution }`（`packages/protocol/src/config.ts:140-145`）：多一个 `paths`（配置文件/角色目录/团队目录的真实路径，「配置文件位置」与「在访达中显示」直接用），`envOverrides` 从 `string[]` 升级为 `EnvOverride[]`（带值与环境变量名，供设置页整行置灰并显示「被 AXON_\* 覆盖」）。
2. `config` 是**脱敏视图** `AxonConfigView`（apiKey = `sk-***bcd`），明文只在主进程（`rawConfig()`）；写侧只认白名单，**未知路径整批拒绝**（不静默吞），错误为 `ConfigIssue[]`（不是 `RoleIssue[]` —— 复用角色错误会把角色语义带进配置面）。
3. 写入是**原子替换 + 0600 权限**，patch 保留配置文件中不认识的键（用户手写的其它字段）。
